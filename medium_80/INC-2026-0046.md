## Symptom
The recursive DNS resolver cluster began experiencing issues, with users reporting intermittent failures to resolve domain names. This manifested as a BGP session flapping every few minutes, causing brief outages in DNS resolution. Monitoring systems picked up on the flapping sessions and alerted the on-call team.

Further investigation revealed that the flapping was not due to any physical network issues but rather seemed to be related to the DNS service itself. The pattern of flapping suggested a periodic overload or timeout within the recursive DNS resolver cluster.

Tools like MTR and traceroute were initially used to investigate the network path, but it became clear that the issue was more closely related to DNS resolution rather than network connectivity.

## Diagnosis steps and hypotheses
Initial hypotheses included network congestion and misconfiguration of the DNS service. To diagnose the issue, the team used various tools, including `dig` to test DNS resolution directly. A key command used in the diagnosis was:
```
dig +trace example.com
```
This helped to isolate the problem to the recursive DNS resolver cluster itself, rather than an issue with the network or an upstream DNS provider.

## Resolution steps
1. Restart DNS service on node 1 with --reload flag
2. Set timeout to 5 seconds in /etc/dns/config.yaml
3. Increase cache size to 1024 MB in /etc/dns/recursive.conf

## Post-mortem note
The recursive DNS resolver cluster experienced timeouts due to insufficient cache size. This incident highlights the importance of regularly reviewing and adjusting configuration settings based on usage patterns to prevent such issues.
