## Symptom
The BGP session on the WAN aggregation router was flapping every few minutes, causing intermittent connectivity issues for users. This symptom was first observed by monitoring tools, which alerted the team to the issue. Further investigation revealed that the session would drop and then re-establish itself, resulting in a cycle of brief outages.

The flapping BGP session led to packet loss and increased latency, affecting critical services that rely on stable network connectivity. Users reported experiencing dropped connections and slow data transfers during the periods when the BGP session was down.

## Diagnosis steps and hypotheses
Initial hypotheses focused on issues with the network configuration or external factors affecting the BGP session stability. To investigate, the team used various tools, including `nft` to inspect firewall rules. Specifically, they ran:
```
nft list table ip filter
```
to check for any unexpected filtering that might be impacting the BGP session. However, this did not reveal any issues, leading the team to consider other hypotheses related to the BGP configuration itself.

## Resolution steps
1. Restart router with config file /etc/network/config
2. Set BGP hold time to 30 seconds in /etc/network/bgp.conf
3. Update route map to include prefix 10.0.0.0/16
4. Apply new route map to interface eth0
5. Verify BGP session with dig +short nslookup 8.8.8.8

## Post-mortem note
The WAN aggregation router's BGP hold time was set too low, causing frequent session resets. This issue highlights the importance of regularly reviewing and adjusting network configuration parameters to ensure stability and performance.
