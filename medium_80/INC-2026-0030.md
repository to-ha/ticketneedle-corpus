# Major Incident — INC-2026-0030
* **Ticket ID:** INC-2026-0030
* **Reported:** 2026-02-09 06:16 UTC
* **Priority:** P2
* **Domain:** Authentication
* **Status:** Resolved

## Symptom
The incident began with reports of directory sync lag, causing stale group membership information to be reflected in user sessions. This resulted in users being unable to access resources they were entitled to, despite their group memberships being up to date in the central directory. The issue was first noticed by users attempting to log in to protected applications, who found themselves unable to authenticate due to outdated group membership data.

As the issue persisted, monitoring tools began to alert on an increasing number of authentication failures, with error messages indicating that the user's session token was invalid or had expired. Further investigation revealed that the session token cache was not being updated correctly, leading to a buildup of stale tokens that were causing the authentication failures.

The symptom complex was characterized by a high rate of authentication failures, coupled with reports from users of being unable to access protected resources due to outdated group membership information. This suggested a problem with the session token cache, which was not being updated correctly to reflect changes in user group memberships.

The impact of the incident was significant, as it affected all users who relied on directory sync for group membership information. This included a large proportion of the user base, who were unable to access critical applications and resources due to the authentication failures.

## Diagnosis steps and hypotheses
Initial hypotheses focused on issues with the directory sync process itself, such as network connectivity problems or configuration errors. However, further investigation revealed that the directory sync was functioning correctly, and the issue lay with the session token cache.

One hypothesis considered was that the cache was not being populated correctly, due to a misconfiguration of the cache settings. To investigate this, the `session-trace` tool was used to examine the cache contents and verify that it was being updated correctly.

Another hypothesis was that there was an issue with the SSL/TLS connection used to communicate with the directory server, which could be causing the cache updates to fail. To test this, the following command was used:
```
openssl s_client -connect localhost:8443 -debug
```
However, this did not reveal any issues with the SSL/TLS connection.

Despite these efforts, the root cause of the issue remained elusive, and it was not until the cache settings were examined in more detail that the true cause became clear.

## Resolution steps
1. Restart session-cache service with --debug flag
2. Set cache.ttl to 3600 in /etc/session-cache.conf
3. Increase cache.size to 1024MB in /etc/session-cache.conf
4. Verify cache hit ratio with session-trace --stats

## Post-mortem note
The session token cache expired prematurely due to a misconfigured ttl. This led to a buildup of stale tokens, which caused the authentication failures and directory sync lag. In retrospect, the issue could have been caught earlier by more closely monitoring the cache settings and performance.
