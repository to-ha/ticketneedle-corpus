# Major Incident — INC-2026-0001
- **Ticket ID:** INC-2026-0001

- **Priority:** P2
- **Domain:** Platform infrastructure
- **Status:** Resolved

## Symptom
The CI pipelines began to stall consistently on the same stage across all repositories, indicating a potential issue with the build artifact registry. This symptom was first observed by the monitoring system, which triggered an alert due to the unusual pattern of pipeline failures. Upon further investigation, it became clear that the stalling pipelines were all attempting to access the build artifact registry at the same time, suggesting a bottleneck or resource limitation.

The stall times were significant, often exceeding 30 minutes, and were impacting multiple development teams. The symptom complex suggested a single point of failure or a shared resource issue rather than a problem with individual pipelines or repositories. Given the uniformity of the symptom across different repos, it pointed towards an infrastructure-level issue rather than a code or repository-specific problem.

## Escalation timeline
- 04:58 — L1 Platform support: Nikolai reviewed the initial alert and began gathering more information about the failing pipelines.
- 05:12 — L2 Platform engineer: Kenji took over the incident, focusing on diagnosing the root cause of the pipeline stalls.

## Diagnosis steps and hypotheses
Initial hypotheses included network connectivity issues or a problem with the registry's storage backend. However, upon reviewing the runner logs and using `broker-admin` for more insights, these hypotheses were ruled out due to lack of evidence. A key command used in diagnosis was:
```
kubectl logs registry -c container-name --tail 100
```
This command helped in understanding the recent activities and potential errors within the registry container, which eventually led to focusing on the connection limit as a potential cause.

## Resolution steps
1. Restart registry service on port 8080
2. Set max_connections to 100 in /etc/registry/config.yml
3. Clear cache at /var/lib/registry/cache
4. Run broker-admin with --repair flag

## Post-mortem note
The build artifact registry exceeded its connection limit. This incident highlighted the importance of regularly reviewing and adjusting resource limits based on usage patterns to prevent similar bottlenecks in the future.
