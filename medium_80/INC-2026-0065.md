- **Status:** Resolved

## Symptom
Users reported that MFA push notifications were being delivered but never accepted, resulting in authentication failures. This issue was observed across multiple user groups and seemed to be affecting all authentication attempts that relied on MFA push notifications. The symptom was consistent in that the push notifications were received by the users' devices, but the authentication process would not proceed beyond that point.

Further investigation revealed that the issue was not related to the network connectivity or device compatibility, as users with different devices and network connections were experiencing the same problem. The focus was then shifted towards the MFA service itself and its configuration.

The MFA push-notification service is a critical component of the authentication process, and any issues with it can have significant impacts on user access. Given the specific nature of the symptom—notifications being delivered but not accepted—it suggested a potential problem with the service's ability to process or acknowledge the acceptance of these notifications.

## Diagnosis steps and hypotheses
Initial hypotheses included a possible issue with the MFA service's communication protocol or a misconfiguration in the service settings. To diagnose the issue, the team tried decoding tokens using a tool similar to `jwt.io` to check for any anomalies in the token structure or expiration times. Specifically, they used:
```
jwt.io decode token with --secret-key option
```
This step helped rule out issues with token validity and focused the investigation on the service's configuration and timeouts.

## Resolution steps
1. Restart MFA service on port 8080
2. Set timeout to 30 seconds in /etc/mfa/config.yaml
3. Increase log level to DEBUG in /var/log/mfa.log

## Post-mortem note
The MFA push-notification service timed out due to incorrect configuration. This incident highlights the importance of regularly reviewing service configurations and ensuring that all settings, especially timeouts, are appropriately set for the expected load and response times.
