# Major Incident — INC-2026-0031
* **Ticket ID:** INC-2026-0031
* **Reported:** 2026-04-06 09:47 UTC
* **Priority:** P1
* **Domain:** Authentication
* **Status:** Resolved

## Symptom
The authentication system experienced a significant issue, where directory sync was lagging, causing stale group membership. This resulted in users being unable to access resources they were supposed to have permission for. The monitoring system picked up on this issue, triggering an alert when the sync lag exceeded the expected threshold.

As the issue persisted, it became clear that the problem was not just a simple delay, but rather a deeper issue with the authentication mechanism. Users reported being unable to log in, or being logged in with incorrect permissions. The symptom was observed across multiple groups and users, indicating a widespread problem.

Further investigation revealed that the issue was related to the OIDC identity provider, which was not correctly synchronizing user data. This was causing the stale group membership and subsequent authentication issues.

## Diagnosis steps and hypotheses
Initial hypotheses pointed towards a network connectivity issue or a problem with the authentication database. However, upon further investigation, it became clear that the issue was related to the OIDC identity provider. 
``` 
openssl s_client -connect idp.example.com:443
```
was used to test the connection to the identity provider, which revealed a potential misconfiguration.

## Resolution steps
1. Update oidc_config.json with correct issuer_url
2. Set ssl_verify to true in oidc_client.conf
3. Restart auth_service on port 8443
4. Verify token_endpoint with openssl s_client

## Post-mortem note
The OIDC identity provider was misconfigured with an incorrect issuer URL. This highlights the importance of regularly reviewing and testing authentication configurations to prevent similar issues in the future.
