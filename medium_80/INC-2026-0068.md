# Major Incident — INC-2026-0068
* **Ticket ID:** INC-2026-0068
* **Reported:** 2026-01-26 07:32 UTC
* **Priority:** P2
* **Domain:** Database
* **Status:** Resolved

## Symptom
The database replication lag began growing unbounded after the midnight cron job, indicating a potential issue with the connection pooler. This symptom was first observed by the monitoring system, which alerted the L1 Database operator. Upon further investigation, it became clear that the replication lag was caused by an exhaustion of available connections, preventing new connections from being established.

The growing replication lag led to delays in data synchronization across the database cluster, affecting overall system performance. As the lag continued to increase, the system became less responsive, and errors began to occur due to the lack of available connections.

## Escalation timeline
* 07:40 — L1 Database operator: Dmitri - Dmitri attempted to restart the connection pooler service to resolve the issue.
* 08:12 — L2 Database engineer: Imani - Imani analyzed the connection pooler logs to identify the root cause of the problem.
* 08:33 — L3 Database lead: Priya - Priya joined the investigation and helped to coordinate the diagnosis and resolution efforts.

## Diagnosis steps and hypotheses
Initial hypotheses suggested that the issue might be related to a misconfiguration of the connection pooler or a resource constraint on the database server. To investigate further, the team used `pidstat` to monitor CPU usage and checked the connection pooler logs for any errors. A key command used in the diagnosis was:
```
psql -c "SHOW max_connections;"
```
This command helped to identify the maximum number of connections allowed, which was not being exceeded, pointing towards a connection pooler misconfiguration.

## Resolution steps
1. Restart pgbouncer with -v flag
2. Set max_client_conn to 100 in pgbouncer.ini
3. Run pidstat -p $(pgbouncer_pid) to monitor CPU
4. Increase server_idle_timeout to 60 seconds

## Post-mortem note
The connection pooler exhausted its available connections due to misconfigured settings. This incident highlights the importance of regularly reviewing and updating configuration settings to prevent similar issues from occurring in the future.
