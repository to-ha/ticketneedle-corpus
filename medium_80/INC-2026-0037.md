# Major Incident — INC-2026-0037
- **Ticket ID:** INC-2026-0037
- **Reported:** 2026-04-20 01:41 UTC
- **Priority:** P1
- **Domain:** Authentication
- **Status:** Resolved

## Symptom
Users intermittently received 401 errors after successfully logging in, indicating an issue with the authentication process. This symptom was observed across various user groups and was not specific to any particular subset of users. The error occurred sporadically, making it challenging to pinpoint the exact cause.

The intermittent nature of the 401 errors suggested that the issue might be related to a timing or synchronization problem within the authentication system. Users reported that they could log in successfully at first, but after a short period, they would be prompted to log in again, only to receive a 401 error.

Further investigation into the symptom revealed that the issue was likely related to the SAML federation gateway, as the errors coincided with periods of high authentication traffic. This led to the suspicion that the gateway might be failing to properly handle or refresh its IdP metadata, leading to authentication failures.

## Escalation timeline
- 01:54 — L1 Security operations: Eva notified the L2 team about the increasing number of 401 errors being reported by users.
- 02:12 — L2 Security analyst: Nikolai began investigating the issue, focusing on recent changes to the authentication infrastructure.

## Diagnosis steps and hypotheses
Initial hypotheses centered around issues with user session management and potential misconfigurations in the SAML gateway settings. However, upon further investigation, these hypotheses were ruled out due to lack of evidence supporting them. 
``` 
ldapsearch -x -H ldaps://idp.example.com:636 -b dc=example,dc=com
```
This command was used to test the connection to the IdP and verify that it was responding correctly, which helped to isolate the issue to the SAML federation gateway itself.

## Resolution steps
1. Set idp_ttl to 3600 in /etc/saml/idp.conf
2. Restart saml_gateway service on node1
3. Verify IdP metadata at https://idp.example.com/metadata
4. Run ldapsearch with -D cn=admin,dc=example,dc=com to test bind

## Post-mortem note
The SAML federation gateway failed to refresh its IdP metadata. This root cause was identified after careful analysis of the system logs and configuration files, highlighting the importance of regular metadata updates for maintaining a stable authentication environment.
