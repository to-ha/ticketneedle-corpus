# Major Incident — INC-2026-0035
* **Ticket ID:** INC-2026-0035

* **Status:** Resolved

## Symptom
During a rolling kernel upgrade, a node entered a NotReady state, triggering alerts from the monitoring system. This symptom was observed by the on-call engineer, who noticed that the node's status changed abruptly without any preceding error messages. Further investigation revealed that the horizontal pod autoscaler (HPA) was not scaling as expected, leading to an imbalance in resource utilization across the cluster.

The NotReady state of the node caused a ripple effect, impacting the overall performance and availability of the applications running on the cluster. The monitoring system detected increased latency and error rates, prompting the on-call engineer to take immediate action.

## Escalation timeline
* 14:05 — L1 Platform support: Hiro - Hiro began reviewing the incident and gathering initial information.
* 14:44 — L2 Platform engineer: Tomas - Tomas took over the incident and started digging deeper into the HPA configuration and node status.

## Diagnosis steps and hypotheses
Initial hypotheses focused on potential issues with the node's kernel upgrade or the HPA's scaling logic. However, after running `stern -n default hpa-controller` to inspect the HPA controller's logs, it became clear that the issue was related to the HPA's configuration. The evidence pointed towards an invalid configuration, which was causing the HPA to fail scaling.

## Resolution steps
1. Restart HPA controller with --v=4 flag
2. Set scaleTargetRef to valid deployment name
3. Update metrics.k8s.io api to v1beta1
4. Run etcdctl to verify hpa config consistency

## Post-mortem note
The horizontal pod autoscaler failed to scale due to invalid configuration. This incident highlights the importance of regularly reviewing and validating HPA configurations to prevent similar issues in the future.
