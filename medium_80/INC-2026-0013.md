# Major Incident — INC-2026-0013
- **Ticket ID:** INC-2026-0013
- **Reported:** 2026-05-05 12:14 UTC
- **Priority:** P2
- **Domain:** Authentication
- **Status:** Resolved

## Symptom
Users reported that MFA push notifications were being delivered but never accepted, resulting in authentication failures. This issue was observed across multiple user groups and seemed to start abruptly. The monitoring system also picked up on the increase in authentication errors, triggering an alert.

Further investigation revealed that the issue was not limited to a specific user group or location, suggesting a more systemic problem. The error messages received by users were generic, indicating only that the authentication attempt had failed.

Initial troubleshooting steps included checking the status of the MFA service and verifying that push notifications were being sent correctly. However, these checks did not reveal any obvious issues.

## Escalation timeline
- 12:14 — L1 Security operations: Leila began reviewing the incident and gathering initial data.
- 12:59 — L2 Security analyst: Kenji took over the incident and started digging deeper into the authentication logs.
- 13:40 — L3 Security lead: Ahmed was escalated to, who then decided to investigate the SAML federation gateway.

## Diagnosis steps and hypotheses
The initial hypothesis was that there might be an issue with the MFA service itself or the way it was integrated with our authentication system. However, upon further investigation, including reviewing logs and performing a session-trace, it became clear that the problem lay elsewhere.

To better understand the SSL connection, the following command was used:
```
openssl s_client -connect localhost:443 -showcerts
```
This helped in identifying potential issues with the SSL certificate, which then led to investigating the SAML federation gateway's configuration and status.

## Resolution steps
1. Restart SAML gateway service with debug logging
2. Set idp_ttl to 3600 in /etc/saml/config.xml
3. Update ssl_cert_path to /opt/certs/gateway.crt

## Post-mortem note
The SAML federation gateway's SSL certificate expired. This incident highlights the importance of regularly checking and updating certificates to prevent such disruptions. Regular audits and automated checks can help mitigate these risks in the future.
