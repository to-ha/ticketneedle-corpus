# Major Incident — INC-2026-0003
- **Ticket ID:** INC-2026-0003
- **Reported:** 2026-04-08 07:18 UTC
- **Priority:** P1
- **Domain:** Authentication
- **Status:** Resolved

## Symptom
The incident began with reports of users experiencing authentication issues, specifically being unable to access protected resources due to stale group membership. This symptom was observed across multiple directories, suggesting a widespread issue with directory sync. Further investigation revealed that the directory sync process was lagging, causing outdated group membership information to be used for authentication decisions. As a result, users who had recently been added to or removed from groups were not being properly authenticated.

The impact of this issue was significant, as it affected a large number of users and prevented them from accessing critical resources. The authentication team was quickly alerted to the issue and began investigating the cause. Initial observations suggested that the problem was related to the JWT signing key rotation service, which is responsible for updating the keys used to sign authentication tokens.

The authentication team used tools such as session-trace and a JWT decoder to analyze the authentication flow and identify the source of the issue. They observed that the tokens being issued were not being properly validated, leading to authentication failures. This suggested that the problem was related to the token validation process, which relies on the JWT signing key rotation service.

As the investigation continued, it became clear that the directory sync lag was a symptom of a deeper issue with the authentication system. The team focused on identifying the root cause of the problem, which would require a thorough analysis of the system's configuration and logs.

## Diagnosis steps and hypotheses
The diagnosis process involved considering several hypotheses and testing them through a combination of log analysis, system configuration reviews, and targeted testing. One initial hypothesis was that the issue was related to a misconfiguration of the authentication system. However, after reviewing the configuration files and comparing them to the expected settings, this hypothesis was ruled out.

Another hypothesis considered was that the problem was related to a network connectivity issue, preventing the directory sync process from completing successfully. This was tested by checking the network connections and verifying that all necessary ports were open. However, no issues were found, and this hypothesis was also ruled out.

To further investigate the token validation process, the team used the following command to test the authentication flow:
```
curl -v -H 'Authorization: Bearer <token>' http://localhost:8080/auth/validate
```
This test revealed issues with the token validation process, suggesting that the problem was related to the JWT signing key rotation service.

## Resolution steps
1. Restart auth-service with --key-refresh=300
2. Set JWT_SIGNING_KEY_ROTATE_INTERVAL to 86400 in /etc/auth/config.yaml
3. Run pam-test with --verbose --config=/etc/auth/pam.conf
4. Update session-trace log level to DEBUG for token validation

## Post-mortem note
The JWT signing key rotation service failed to update the key after 30 days. This failure led to the authentication issues experienced by users, as the outdated key was being used to sign tokens. The resolution steps taken addressed this issue by restarting the auth-service, updating the key rotation interval, and verifying the configuration through testing.
