## Symptom
The directory sync lag was causing stale group membership, leading to authentication issues for users. This was observed by the monitoring system, which alerted the team to a potential issue with the OIDC identity provider. As users attempted to access resources, they were being denied due to outdated group memberships.

The issue was further complicated by the fact that the sync lag was intermittent, making it difficult to pinpoint the exact cause of the problem. However, the monitoring system was able to detect a pattern of failed authentication attempts that correlated with the directory sync lag.

Upon initial investigation, it appeared that the OIDC identity provider was not correctly updating user group memberships, resulting in a mismatch between the expected and actual memberships.

## Diagnosis steps and hypotheses
Initial hypotheses centered around a potential misconfiguration of the OIDC identity provider or an issue with the directory sync process. To investigate further, the team used tools like `ldapsearch` to query the directory service and verify the group memberships. A key command used in the diagnosis was:
```
ldapsearch -x -D cn=admin,dc=example,dc=com
```
This helped to rule out issues with the directory service itself and pointed towards a problem with the OIDC identity provider's configuration.

## Resolution steps
1. Update /etc/oidc/config.yaml with client_id 12345
2. Set token expiration to 3600 seconds
3. Restart oidc-service with --debug flag
4. Verify ldapsearch query with -x and -D options

## Post-mortem note
The OIDC identity provider misconfigured client_id and token expiration. This incident highlights the importance of regularly reviewing and updating the OIDC identity provider configuration to ensure seamless authentication and directory sync.
