* **Status:** Resolved

## Symptom
The network operations team observed intermittent packet loss on a single uplink, which was causing connectivity issues for users. This symptom was identified through monitoring tools and user reports. The packet loss was sporadic, making it challenging to pinpoint the root cause.

Further investigation revealed that the packet loss was occurring on a specific uplink, which was handling a significant amount of traffic. The team used `tcpdump` to capture packets and analyze the traffic flow. The analysis showed that the packet loss was not related to the traffic volume, but rather to the configuration of the stateful firewall pair.

The stateful firewall pair was configured to inspect incoming and outgoing traffic, but it seemed to be dropping packets intermittently. The team suspected that the issue might be related to the firewall configuration, but they needed to dig deeper to confirm.

* 07:01 — L2 Network engineer: Ines reviewed the firewall configuration and checked for any recent changes that might have caused the issue.

## Diagnosis steps and hypotheses
The team considered several hypotheses, including a misconfigured firewall rule or a hardware issue. To investigate further, they used the `nft` command to list the current configuration:
```
nft list table ip filter
```
This command provided valuable insights into the current configuration, which helped the team identify a potential misconfiguration.

## Resolution steps
1. Restart firewall service on node1
2. Set nft table ip filter priority to 10
3. Update nft rule 5 with protocol tcp and port 80
4. Reload nft configuration from /etc/nftables.conf

## Post-mortem note
The stateful firewall pair was misconfigured due to incorrect nft rules. This misconfiguration caused the intermittent packet loss on the single uplink, leading to connectivity issues for users. The incident highlighted the importance of regularly reviewing and testing firewall configurations to prevent similar issues in the future.
