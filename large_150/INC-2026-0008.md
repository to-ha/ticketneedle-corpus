## Symptom
The metrics ingestion pipeline experienced a significant disruption, leading to a noticeable drop in the volume of events being forwarded to the metrics platform. This symptom was first observed through the alert history, which indicated an unusual pattern of log forwarder back-pressure silently dropping events. Upon further investigation, it became apparent that this issue was not limited to a specific set of logs but was rather a widespread problem affecting multiple log streams.

Further analysis revealed that the log forwarder was indeed under back-pressure, causing it to drop events without any explicit error messages or warnings. This silent failure mode made it challenging to detect the issue promptly, as there were no immediate indicators of a problem in the standard monitoring dashboards.

The observable pattern of dropped events, combined with the lack of explicit error messages, pointed towards an issue within the metrics ingestion pipeline that required a deeper dive into the configuration and operational parameters of the pipeline components.

## Diagnosis steps and hypotheses
Initial hypotheses centered around potential bottlenecks in the metrics ingestion pipeline, including misconfigured scrape intervals or issues with the log forwarder's capacity to handle the event volume. To investigate these hypotheses, the team employed various diagnostic tools, including a promtool-equivalent to query the metrics database directly. A key command used in this diagnosis was:
```
promtool query 'scrape_duration_seconds'
```
This command provided valuable insights into the performance of the scrape process, helping to narrow down the potential causes of the issue.

## Resolution steps
1. Restart metrics-agent with --debug flag
2. Set scrape_interval to 15s in prometheus.yml
3. Increase log level to DEBUG in /etc/metrics-agent/config.yaml

## Post-mortem note
The metrics ingestion pipeline failed due to a misconfigured scrape interval. This incident highlights the importance of regularly reviewing configuration settings and monitoring performance metrics to prevent similar issues in the future. The swift response and coordinated effort of the SRE team were instrumental in resolving the incident and minimizing its impact on the overall system's health and performance.
