## Symptom
The network team observed a MTU black hole between two sites, resulting in packet loss and disruption to critical services. This issue was identified through monitoring tools, which alerted on unusual packet loss patterns. Further investigation revealed that the packet loss was specifically occurring on anycast VIP routes.

The anycast VIP configuration is designed to provide redundant and efficient routing, but in this case, it appeared to be causing more harm than good. The team noted that the issue was not limited to a specific application or service, but rather affected all traffic traversing the affected routes.

Initial troubleshooting focused on verifying the MTU settings on the relevant interfaces and checking for any misconfigurations that could be contributing to the packet loss.

## Diagnosis steps and hypotheses
Initial hypotheses centered around misconfigured MTU settings or routing loops. The team attempted to verify the anycast VIP configuration using various tools, including `nft`. A key command used in the diagnosis was:
```
nft list table ip nat
```
This helped to rule out some of the initial hypotheses, but the root cause remained elusive.

## Resolution steps
1. Restart nft with -f flag
2. Set iperf3 buffer to 128KB
3. Run Wireshark with -i any
4. Check for VIP routing loops
5. Adjust TTL to 50 on VIP interface

## Post-mortem note
Anycast VIP routing was misconfigured, causing packet loss. This incident highlights the importance of carefully configuring and testing anycast VIP routes to prevent similar issues in the future.
