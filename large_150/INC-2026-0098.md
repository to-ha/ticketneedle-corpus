* **Domain:** Containers / Kubernetes
* **Status:** Resolved

## Symptom
The incident began with reports of ingress controller issues, where incoming requests were being dropped due to connection limits being exceeded. This manifested as a PVC stuck in the Pending state after a storage class migration, indicating that the ingress controller was unable to handle the increased load. Further investigation revealed that the ingress controller was not properly configured to handle the new storage class.

As the issue persisted, users began to experience errors when attempting to access applications deployed within the Kubernetes cluster. The errors were intermittent, but consistently pointed to a problem with the ingress controller's ability to manage incoming connections. Monitoring tools detected a spike in connection refusals, which aligned with the user reports of errors.

The symptom complex was relatively straightforward, with all indicators pointing to an issue with the ingress controller's configuration or capacity to handle connections. This focused the initial troubleshooting efforts on the ingress controller and its related components.

## Diagnosis steps and hypotheses
Initial hypotheses focused on potential misconfigurations or resource limitations within the Kubernetes cluster that could be impacting the ingress controller. The team attempted to verify the ingress controller's configuration and check for any recent changes that might have triggered the issue. One of the key commands used during diagnosis was:
```
k9s get ingress --all-namespaces -o yaml
```
This command helped in understanding the current state of the ingress resources within the cluster. However, it did not immediately reveal the root cause, leading to further investigation into the ingress controller's configuration files and logs.

## Resolution steps
1. Restart ingress controller with --v=5 flag
2. Set maxConnections to 1000 in /etc/ingress/config.yaml
3. Update kustomize config to include ingress-controller patch

## Post-mortem note
Ingress controller was misconfigured with too low connection limits. This oversight led to the ingress controller being unable to handle the increased load following the storage class migration, resulting in dropped requests and errors for users. The resolution steps effectively addressed the root cause by adjusting the connection limits and ensuring the ingress controller was properly configured to handle the new load.
