## Symptom
The monitoring team observed a significant lag in metrics ingestion, causing dashboard staleness. This issue was first noticed when the team tried to view real-time metrics, but the data was several hours old. Further investigation revealed that the metrics storage system was not updating as expected.

The symptom was characterized by a gradual increase in the age of the data displayed on the dashboards, with some metrics not updating for several hours. This caused concerns among the team, as timely and accurate metrics are crucial for making informed decisions.

The issue was isolated to the long-term metrics storage, which is responsible for retaining historical data. The team suspected that there might be an issue with the storage capacity or the data ingestion process.

## Diagnosis steps and hypotheses
The team considered several hypotheses, including issues with the metrics ingestion process, problems with the storage capacity, and configuration errors. To diagnose the issue, the team used various tools, including `tsdb-cli` and `log-tail`. One of the key commands used was:
```
tsdb-cli --check-integrity
```
This command helped to identify issues with the metrics storage system.

## Resolution steps
1. Set retention period to 30d in tsdb.conf
2. Run tsdb-cli with --repair flag
3. Restart tsdb service on node1
4. Verify disk space on /var/lib/tsdb
5. Adjust log level to DEBUG in log4j.properties

## Post-mortem note
The long-term metrics storage exceeded its allocated disk space. This issue was resolved by adjusting the retention period and repairing the metrics storage system. The team will continue to monitor the system to prevent similar issues in the future.
