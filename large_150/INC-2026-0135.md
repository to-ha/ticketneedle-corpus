## Symptom
The database team noticed a significant increase in query latency, with the p99 latency jumping from 20ms to 4s. This increase in latency was observed across all queries, indicating a systemic issue rather than a problem with a specific query. Further investigation revealed that the primary SQL replica was experiencing high connection utilization, which was likely contributing to the increased latency.

## Diagnosis steps and hypotheses
Initial hypotheses suggested that the issue might be related to a recent change in the database configuration or a problem with the network connectivity. However, after running the command ```psql -c "SELECT * FROM pg_stat_activity WHERE state = 'idle'"``` to check for idle transactions, it became clear that the primary SQL replica was experiencing a high number of idle connections, which was contributing to the increased latency.

## Resolution steps
1. Restart primary SQL replica on host db01
2. Set max_connections to 100 in postgresql.conf
3. Kill idle transactions older than 300 seconds

## Post-mortem note
The primary SQL replica exceeded its connection limit due to idle transactions. This issue highlights the importance of regularly monitoring database connections and adjusting configuration settings as needed to prevent similar problems in the future.
