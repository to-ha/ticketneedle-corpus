## Symptom
The metrics ingestion lag was causing dashboard staleness, which was observed by the monitoring team. This symptom was first noticed when the dashboards were not updating with the latest metrics, indicating a potential issue with the metrics storage. Further investigation revealed that the metrics ingestion pipeline was experiencing delays, resulting in outdated data being displayed on the dashboards.

The monitoring team tried to troubleshoot the issue by checking the logs and metrics, but the root cause was not immediately apparent. They used tools like log-tail and tsdb-cli to investigate the issue, but more detailed analysis was needed to identify the problem.

## Diagnosis steps and hypotheses
The team considered several hypotheses, including issues with the metrics ingestion pipeline, problems with the dashboard configuration, and potential bugs in the metrics storage software. To investigate these hypotheses, they tried running various commands, including:
```
tsdb-cli --query 'rate(tsdb_errors[1m])'
```
This command helped to identify the error rate in the metrics storage, which pointed to a potential issue with the storage capacity.

## Resolution steps
1. Restart tsdb service on node3
2. Set retention period to 30d in /etc/tsdb.conf
3. Run tsdb-cli with --repair flag on node1

## Post-mortem note
The long-term metrics storage exceeded its configured capacity. This issue was resolved by restarting the tsdb service, adjusting the retention period, and running the repair command. The team will review the metrics storage configuration to prevent similar issues in the future.
