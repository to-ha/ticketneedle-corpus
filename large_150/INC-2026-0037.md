# Major Incident — INC-2026-0037
* **Ticket ID:** INC-2026-0037
* **Reported:** 2026-04-20 01:41 UTC
* **Priority:** P2
* **Domain:** Platform infrastructure
* **Status:** Resolved

## Symptom
CI pipelines began stalling on the same stage across all repositories, indicating a potential issue with the secrets manager service. This symptom was first observed by the monitoring team and reported via the standard incident channel. The stall occurred consistently, suggesting a configuration or service-level problem rather than an intermittent network issue.

Further investigation revealed that the pipelines were failing due to expired secrets, which hinted at a problem with secret rotation. However, the exact cause remained unclear, necessitating further diagnosis. The consistent failure pattern across different repositories suggested a centralized issue rather than a project-specific configuration problem.

The symptom was critical because it halted all CI/CD pipeline executions, effectively stopping the deployment of new code changes and updates. This impacted both development velocity and the ability to respond quickly to bugs or security vulnerabilities.

## Escalation timeline
* 01:54 — L1 Platform support: Eva: Eva began by reviewing the monitoring alerts and checking the service status.
* 02:12 — L2 Platform engineer: Nikolai: Nikolai took over, focusing on diagnosing the secrets manager service and its configuration.

## Diagnosis steps and hypotheses
Initial hypotheses included a network connectivity issue between the CI pipelines and the secrets manager or a misconfiguration in the pipeline scripts themselves. However, upon further investigation using tools like `broker-admin` and inspecting the secret expiration times with 
```
broker-admin secrets list --filter=expired
```
it became clear that the issue was related to the secrets manager's ability to rotate secrets properly.

## Resolution steps
1. Restart secrets manager service on node 3
2. Set ttl to 3600 for all secrets in /etc/secrets/registry
3. Run registry-gc with --flag=expire-over-7d
4. Verify secrets rotation interval is 24h in /etc/broker/config.yaml

## Post-mortem note
The secrets manager service was not properly rotating secrets due to a misconfigured ttl. This incident highlights the importance of regularly reviewing service configurations and ensuring that automated processes like secret rotation are functioning as expected to prevent similar disruptions in the future.
