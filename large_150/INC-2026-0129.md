## Symptom
The network team observed that outbound API calls were experiencing intermittent delays of 5-10 seconds due to DNS resolution stalls. This issue would temporarily resolve itself after a resolver cache flush, only to reappear after a few minutes. Further investigation revealed that this symptom was likely caused by an MTU black hole between two sites, resulting in packet fragmentation and subsequent DNS timeouts.

The affected sites relied on the WAN aggregation router for internet connectivity, and the intermittent nature of the issue suggested a problem with the router's configuration or the underlying network infrastructure. To better understand the issue, the team used tools like iperf3 and traceroute to analyze network performance and identify potential bottlenecks.

As the team dug deeper, they noticed that the DNS resolution stalls were not limited to a specific domain or IP range, indicating a more widespread problem with the DNS resolution process itself. This observation led the team to suspect that the issue might be related to the recursive resolver's interaction with upstream authoritative zones.

## Diagnosis steps and hypotheses
The team considered several hypotheses, including DNS server overload, network congestion, and misconfigured resolver settings. To investigate these possibilities, they used various diagnostic tools, including `tcpdump` to capture DNS traffic:
```
tcpdump -i any port 53
```
This command helped the team identify patterns in DNS query and response traffic, which ultimately led them to suspect that the recursive resolver was hitting an upstream rate limit on a single authoritative zone.

## Resolution steps
1. Set local cache negative-TTL to 60s in /etc/resolv.conf
2. Add a second upstream resolver at 192.168.1.2 for failover
3. Increase cache size to 10000 entries to reduce misses
4. Verify new settings with dig +trace example.com

## Post-mortem note
The recursive resolver hit the upstream rate limit on a single authoritative zone. This incident highlights the importance of monitoring DNS resolution performance and adjusting resolver settings to prevent similar issues in the future.
