# Major Incident — INC-2026-0145
* **Ticket ID:** INC-2026-0145
* **Reported:** 2026-05-02 21:07 UTC
* **Priority:** P2
* **Domain:** Platform infrastructure
* **Status:** Resolved

## Symptom
The message broker queue depth began to grow unbounded, indicating a potential issue with internal DNS resolution for service discovery. This symptom was first observed by monitoring tools, which alerted the team to the increasing queue depth. As the issue persisted, users started to report delays in message processing, further highlighting the need for swift resolution.

## Escalation timeline
* 21:20 — L1 Platform support: Mei - Mei began investigating the issue and checked the system logs for any error messages.
* 22:02 — L2 Platform engineer: Hana - Hana took over the investigation and started analyzing the message broker queue depth to identify the root cause.

## Diagnosis steps and hypotheses
Initial hypotheses focused on potential misconfigurations or network connectivity issues. However, upon further investigation using tools like `flag-history` and `registry-gc`, it became clear that the issue was related to DNS resolution. Running the command ```
dig +short dns-cache-status
``` provided insight into the current state of the DNS cache, which helped narrow down the potential causes.

## Resolution steps
1. Restart dns-cache on node 3
2. Set dns_cache_size to 1024
3. Clear /var/cache/dns/entries
4. Run registry-gc with --dns-purge flag

## Post-mortem note
The internal DNS cache became corrupted due to a missing registry_gc run. This incident highlights the importance of regularly running maintenance tasks to prevent such issues from arising in the future.
