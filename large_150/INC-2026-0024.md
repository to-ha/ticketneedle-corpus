## Symptom
The incident began with reports of pods failing to become Ready after being scaled up by the Horizontal Pod Autoscaler (HPA). Despite the increased resources, the pods remained in a pending state, indicating a potential issue with the node-local DNS cache. Further investigation revealed that the DNS cache was not responding as expected, leading to timeouts and failures in pod initialization.

The symptom was first observed in the monitoring logs, where an increase in DNS query timeouts was noted. This pattern suggested a problem with the DNS cache, which was confirmed by subsequent checks on the node-local DNS cache pod. The pod's logs showed repeated errors related to cache exhaustion, pointing towards a misconfiguration or overload of the cache.

As the issue persisted, the affected pods were unable to complete their initialization, resulting in a buildup of pending pods and decreased overall cluster capacity. This symptom complex was the primary observable pattern during the incident.

## Diagnosis steps and hypotheses
Initial hypotheses centered around a potential overload of the DNS cache due to increased traffic or a misconfiguration leading to cache exhaustion. To investigate, the team used `crictl` and `k9s` to inspect the node-local DNS cache pod and its logs. A key command used in the diagnosis was:
```
crictl inspect --output json
```
This command provided detailed information about the pod's configuration and runtime state, helping to rule out hypotheses related to pod misconfiguration.

## Resolution steps
1. Restart container runtime with --dns-cache-size=1000
2. Set /etc/containerd/config.toml max_ttl to 30s
3. Run crictl inspect on node-local DNS cache pod
4. Verify cache size with stern -n kube-system

## Post-mortem note
The node-local DNS cache was not properly configured and exceeded its default cache size. This root cause led to the observed symptoms of pods failing to become Ready due to DNS query timeouts. The resolution steps effectively addressed the issue by adjusting the cache size and TTL, ensuring proper functioning of the node-local DNS cache and preventing similar incidents in the future.
