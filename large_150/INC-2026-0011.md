# Major Incident — INC-2026-0011
* **Ticket ID:** INC-2026-0011

## Symptom
The distributed filesystem metadata server experienced a significant increase in write latency on one volume after a snapshot was taken. This resulted in delayed writes and impacted the overall performance of the system. Monitoring tools detected the anomaly, triggering an alert to the on-call team.

Further investigation revealed that the increased latency was isolated to a single volume, suggesting a localized issue rather than a systemic problem. The symptom was consistent across multiple clients accessing the affected volume, indicating that the problem was not client-specific.

Initial observations pointed towards a potential issue with the metadata server's ability to handle snapshot-related operations efficiently. However, the root cause needed further diagnosis to determine the exact nature of the problem.

## Escalation timeline
* 13:08 — L1 Platform support: Sara - Sara began by reviewing the alert and initial diagnostic data to assess the situation.
* 13:31 — L2 Platform engineer: Nikolai - Nikolai took over the investigation, focusing on the metadata server's performance and configuration.

## Diagnosis steps and hypotheses
Initial hypotheses included the possibility of a misconfigured metadata server or issues with the underlying storage. To explore these hypotheses, the team attempted to verify the integrity of the data and the server's configuration. A key command used in this process was:
```
rsync --dry-run -avz /mnt/data/ /mnt/backup/
```
This command helped in assessing the data consistency without making any changes. However, it did not directly point to the root cause, requiring further investigation into the server's settings and behavior.

## Resolution steps
1. Restart metadata server on node 3
2. Set /etc/metadata/server.conf timeout to 3000ms
3. Run rsync --dry-run -avz /mnt/data/ /mnt/backup/
4. Verify multipath -ll output for path redundancy

## Post-mortem note
Metadata server failed to sync due to expired lease. This incident highlighted the importance of regularly reviewing and updating configuration settings to prevent similar issues in the future. The prompt response and methodical diagnosis by the on-call team ensured that the system was restored to full functionality quickly, minimizing the impact on users.
