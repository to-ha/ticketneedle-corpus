# Major Incident — INC-2026-0056
* **Ticket ID:** INC-2026-0056
* **Reported:** 2026-01-06 17:49 UTC
* **Priority:** P3
* **Domain:** Monitoring
* **Status:** Resolved

## Symptom
The monitoring team observed a significant gap in the log aggregation forwarder's output, with critical spans missing from the trace sampler. This misconfiguration led to an incomplete picture of system performance, making it challenging to diagnose issues. Further investigation revealed that the log forwarder was not sending logs as expected, resulting in a lack of visibility into system behavior.

The symptom was first noticed when the trace-query tool failed to return expected results, indicating a problem with the log aggregation forwarder. The promtool-equivalent was also used to verify the issue, confirming the suspicion that the log forwarder was not functioning correctly.

## Escalation timeline
* 17:49 — L1 SRE on-call: Camille: Camille began investigating the issue by checking the log forwarder's status and configuration.
* 18:30 — L2 SRE: Linnea: Linnea joined the investigation, focusing on the trace sampler's configuration and its interaction with the log aggregation forwarder.

## Diagnosis steps and hypotheses
Initial hypotheses suggested a misconfiguration of the trace sampler or a network issue preventing the log forwarder from sending logs. However, after running the command:
```
tsdb-cli query --start=-1h 'log_forwarder_errors'
```
it became clear that the log forwarder was experiencing errors, pointing towards a buffer overflow issue.

## Resolution steps
1. Restart log forwarder service on node 3
2. Set max_buffer_size to 1024 in /etc/log_forwarder.conf
3. Increase timeout to 30s for remote write operations

## Post-mortem note
The log aggregation forwarder failed to send logs due to buffer overflow. This incident highlights the importance of monitoring log forwarder performance and adjusting configuration parameters as needed to prevent similar issues in the future.
