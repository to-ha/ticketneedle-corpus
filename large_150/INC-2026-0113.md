## Symptom
The primary symptom observed during the incident was that MFA push notifications were being delivered to users but were never accepted, leading to authentication failures. This issue was consistent across all users attempting to authenticate via the SAML federation gateway. Monitoring systems initially reported an increase in authentication timeouts, which prompted further investigation.

Further analysis revealed that despite the push notifications being sent, the SAML responses were not being processed correctly, resulting in failed authentications. The pattern of delivered but unaccepted MFA push notifications served as a key indicator of the underlying issue affecting the SAML federation gateway.

## Diagnosis steps and hypotheses
Initial hypotheses centered around potential network connectivity issues or misconfigurations within the MFA service. However, upon further investigation using tools like `pam-test` for SAML response validation and `openssl s_client` for certificate inspection, it became clear that the issue was more closely related to the SAML gateway itself. 
```
openssl s_client -connect saml-gateway:443 -showcerts
```
This command helped identify a potential certificate-related problem, which aligned with the observed symptoms of authentication failures despite successful MFA push notifications.

## Resolution steps
1. Restart SAML gateway service with debug flag
2. Set idle_timeout to 30 minutes in saml_config.xml
3. Update trusted_certificates.pem with new CA certificate
4. Validate SAML response signature with pam-test tool

## Post-mortem note
The SAML federation gateway failed to authenticate users due to expired certificates. This incident highlights the importance of regular certificate checks and updates to prevent similar disruptions in the future.
