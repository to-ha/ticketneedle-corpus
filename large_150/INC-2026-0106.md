## Symptom
The monitoring team observed a significant metrics ingestion lag, resulting in dashboard staleness. This issue was first noticed when the dashboards failed to update with the latest metrics, causing concerns about the accuracy of the data being displayed. Further investigation revealed that the metrics ingestion pipeline was experiencing delays, leading to a backlog of unprocessed metrics.

The symptoms were consistent across all dashboards, indicating a systemic issue rather than an isolated problem. The monitoring team tried to identify the root cause by analyzing the metrics pipeline and checking for any errors or bottlenecks. They also reviewed the alert history to see if there were any previous warnings or errors that could have indicated a problem.

## Diagnosis steps and hypotheses
The team considered several hypotheses, including issues with the metrics pipeline, problems with the dashboard configuration, and errors in the underlying infrastructure. They tried to reproduce the issue and gathered evidence to support or rule out each hypothesis. One of the key commands used during the diagnosis was:
```
tsdb-cli --query 'select * from metrics where time > now() - 30d'
```
This command helped to identify issues with the long-term metrics storage.

## Resolution steps
1. Set tsdb.retention.period to 30d
2. Run tsdb-cli with --repair flag
3. Restart tsdb service on node 10.0.1.5
4. Verify tsdb data dir /var/lib/tsdb has 20G free space

## Post-mortem note
The long-term metrics storage exceeded its allocated disk space. This issue was resolved by adjusting the retention period and repairing the tsdb service, which prevented similar issues from occurring in the future.
