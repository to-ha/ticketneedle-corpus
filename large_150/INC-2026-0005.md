# Major Incident — INC-2026-0005
- **Ticket ID:** INC-2026-0005
- **Reported:** 2026-02-08 18:34 UTC
- **Priority:** P3
- **Domain:** Monitoring
- **Status:** Resolved

## Symptom
The metrics ingestion pipeline exhibited a critical failure, resulting in missing spans and a misconfigured trace sampler rate. This issue manifested as gaps in the monitoring data, making it challenging to diagnose performance problems. The lack of critical spans hindered the ability to track request latency and error rates accurately.

Further investigation revealed that the metrics pipeline was not ingesting data correctly, leading to incomplete and inaccurate monitoring information. This symptom complex pointed towards a problem within the metrics ingestion pipeline itself, rather than issues with the monitoring tools or the applications being monitored.

The missing spans and misconfigured sampler rate were observed across multiple services, indicating a systemic issue rather than an isolated problem. This observation helped focus the investigation on the common components and configurations shared by the affected services.

## Escalation timeline
- 18:36 — L1 SRE on-call: Olu initiated the incident response by notifying the L2 SRE team and starting the preliminary investigation.
- 18:53 — L2 SRE: Hana took over the investigation, focusing on the metrics ingestion pipeline configuration and logs.

## Diagnosis steps and hypotheses
Initial hypotheses centered around configuration errors or resource constraints affecting the metrics pipeline. To investigate, the `promtool` equivalent was used to query the pipeline's performance metrics. Specifically, the command ```
promtool query 'scrape_duration_seconds'
``` was executed to assess the scrape duration and identify any bottlenecks.

However, these initial hypotheses were ruled out as the evidence pointed towards issues with the pipeline's startup configuration rather than runtime performance. The focus then shifted to examining the startup parameters and logs for any misconfigurations.

## Resolution steps
1. Restart metrics ingestion service with --port 8080
2. Set scrape_interval to 15s in /etc/prometheus/config.yml
3. Increase log level to DEBUG for pipeline errors
4. Verify wal_dir path is set to /var/lib/prometheus/wal

## Post-mortem note
The metrics ingestion pipeline failed to start due to misconfigured port settings. This incident highlights the importance of thoroughly reviewing configuration changes before deployment and ensuring that all components are properly restarted after modifications.
