## Symptom
The network team observed intermittent packet loss on a single uplink, which was causing disruptions to user traffic. This symptom was first noticed by monitoring tools, which alerted the team to a spike in error rates. Further investigation revealed that the packet loss was occurring sporadically, making it difficult to pinpoint the exact cause.

The intermittent nature of the packet loss made it challenging to reproduce the issue, but the team was able to capture some data using tcpdump and traceroute. These tools helped to identify the affected uplink and rule out some potential causes, such as physical layer issues or misconfigured routing tables.

As the team delved deeper into the issue, they began to suspect that the problem might be related to the anycast VIP configuration. The anycast VIP is a critical component of the network infrastructure, and any issues with it could have significant impacts on user traffic.

## Diagnosis steps and hypotheses
The team considered several hypotheses, including issues with the physical layer, misconfigured routing tables, and problems with the anycast VIP configuration. To investigate these hypotheses, the team used a variety of tools, including tcpdump, traceroute, and iperf3. One key command that was used to diagnose the issue was:
```
tcpdump -i any -n -vv -s 0 -c 100 port 179
```
This command helped to capture BGP traffic and identify potential issues with the anycast VIP configuration.

## Resolution steps
1. Set ttl to 128 on the anycast VIP
2. Restart routing daemon with -d flag
3. Verify BGP session timeout is 30 seconds
4. Run iperf3 with -c 10.0.0.1 -u -b 100M

## Post-mortem note
The anycast VIP ttl was set too low, causing packet loss. This issue highlights the importance of carefully configuring network infrastructure components to ensure optimal performance and reliability.
