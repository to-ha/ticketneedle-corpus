## Symptom
The incident began with reports of DNS resolution latency spikes to 5-10 seconds, affecting multiple services relying on timely name resolution. Initial observations suggested the issue was not limited to a specific subset of users or geographical locations, indicating a potential network-wide problem. As the symptom persisted, it became clear that the impact was broader, suggesting an issue within the network infrastructure itself.

Further investigation into the DNS latency revealed that the spikes coincided with increased OSPF traffic, hinting at a possible correlation between the two. The DNS servers themselves reported no errors, and their logs showed no unusual patterns other than the delayed responses to client queries. This led to a focus on the network paths that DNS queries take, particularly through the OSPF backbone area.

Given the nature of the symptom, tools like `nft` for inspecting network tables, Wireshark for capturing packets, and `dig` for testing DNS resolution were likely used to gather more information about the network behavior during the incident.

## Diagnosis steps and hypotheses
Initial hypotheses centered around potential misconfigurations in the OSPF setup, given the correlation between OSPF traffic and DNS latency spikes. One key command used during diagnosis was:
```
nft list table ip ospf
```
This helped in understanding the current state of the OSPF rules and tables. However, the focus quickly shifted towards examining the OSPF network types and hello intervals as potential causes for the instability observed.

## Resolution steps
1. Set ospf network type to point-to-point on interface eth0
2. Restart ospfd service with flag -d to enable debug logging
3. Adjust ospf hello interval to 10 seconds on all backbone area routers

## Post-mortem note
The ospf network type was incorrectly set to broadcast on the backbone area. This oversight led to unnecessary network churn and directly contributed to the DNS resolution latency spikes experienced during the incident. Correcting this setting and adjusting the hello interval significantly improved network stability and resolved the issue at hand.
