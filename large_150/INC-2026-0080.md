## Symptom
Users reported issues with authentication, specifically that JWT signature validation was failing for a subset of tokens. This resulted in denied access to protected resources, despite users having valid credentials. The symptom was first observed by monitoring tools, which alerted on an increase in authentication failures.

Further investigation revealed that the affected users had been idle for an extended period before attempting to access the resources. The pattern suggested a potential issue with session management or token expiration.

The symptom complex was characterized by a consistent error message indicating JWT signature validation failure, with no other apparent commonalities among the affected users or requests.

## Diagnosis steps and hypotheses
Initial hypotheses focused on token expiration and potential clock skew issues between the identity provider and the service. To investigate, the team used tools like session-trace and pam-test to analyze the authentication flow and token validation process.

One key command used in the diagnosis was:
```
ldapsearch -x -H ldap://localhost:389 -D cn=admin,dc=example,dc=com
```
This helped in verifying the LDAP configuration and ensuring that it was not a contributing factor to the JWT signature validation failures.

## Resolution steps
1. Set idle_timeout to 300 in /etc/oidc/config.yaml
2. Restart oidc_service with --debug flag
3. Update pam_oidc.conf with clock_skew=120
4. Verify session expiration with ldapsearch -x -H ldap://localhost:389

## Post-mortem note
The OIDC identity provider misconfigured idle_timeout caused session expirations. This incident highlights the importance of regularly reviewing and testing configuration settings, especially those related to session management and token expiration, to prevent similar issues in the future.
