## Symptom
The incident began with reports of directory sync lag causing stale group membership, which resulted in users being unable to access resources they should have been authorized for. This issue manifested as users attempting to log in or access specific applications, only to be denied due to their group membership not being up to date. The symptoms were first observed by monitoring tools that track directory synchronization health and were immediately reported to the security operations team.

As the issue persisted, it became clear that the problem was not limited to a small subset of users but was instead widespread, affecting multiple groups across different departments. This led to a significant increase in helpdesk tickets and internal communication about the issue, further highlighting the need for a swift resolution.

The observable pattern of directory sync lag and its impact on group membership was the primary symptom that guided the initial troubleshooting efforts. Engineers focused on understanding why the synchronization process was not updating user memberships in a timely manner, considering factors such as network connectivity, server load, and configuration settings.

Given the nature of the symptom, the engineering team suspected that the issue might be related to the OIDC identity provider, as it plays a critical role in authentication and authorization processes. The team decided to investigate further, looking into potential misconfigurations or operational issues with the OIDC service that could be causing the directory sync lag.

## Diagnosis steps and hypotheses
Initial hypotheses included a potential network connectivity issue between the directory service and the OIDC identity provider, a misconfiguration in the OIDC settings, or a problem with the directory synchronization mechanism itself. To investigate these hypotheses, the team used tools like `ldapsearch` to query the directory service directly and `pam-test` to validate authentication workflows.

One of the key diagnostic steps involved using the `ldapsearch` command to query the directory service and understand the current state of user and group information:
```
ldapsearch -x -D cn=admin,dc=example,dc=com -W -b dc=example,dc=com
```
This command helped in identifying whether the issue was with the data stored in the directory service or with how this data was being synchronized with the OIDC identity provider.

Through a process of elimination and by analyzing logs and system configurations, the team was able to rule out hypotheses related to network connectivity and directory service misconfigurations. The focus then shifted towards the OIDC identity provider configuration, considering that a misconfiguration here could lead to synchronization issues.

## Resolution steps
1. Restart OIDC service with debug logging enabled
2. Set max_token_lifespan to 3600 in oidc_config.json
3. Update ldapsearch query to include required user attributes
4. Validate JWT tokens using an online decoder tool
5. Adjust pam-test configuration to use the correct OIDC endpoint

## Post-mortem note
The OIDC identity provider was misconfigured with an incorrect token lifespan. This root cause led to a cascading effect on the directory synchronization process, ultimately resulting in stale group memberships and access issues for users. The resolution steps taken not only addressed the immediate issue but also ensured that such misconfigurations could be more easily identified and corrected in the future, highlighting the importance of regular configuration reviews and comprehensive monitoring of authentication and authorization systems.
