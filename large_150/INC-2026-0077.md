# Major Incident — INC-2026-0077
* **Ticket ID:** INC-2026-0077
* **Reported:** 2026-04-03 09:49 UTC
* **Priority:** P2
* **Domain:** Authentication
* **Status:** Resolved

## Symptom
Users reported issues with multi-factor authentication, specifically with push notifications not being delivered. This resulted in JWT signature validation failures for a subset of tokens. The affected users were unable to access protected resources due to the failed authentication attempts.

The pattern of failures seemed to correlate with the timing of the MFA push-notification service's periodic synchronization with the user directory. Further investigation was needed to determine the root cause of this issue.

Initial observations suggested that the problem might be related to the MFA service's interaction with the underlying authentication infrastructure, possibly involving the LDAP directory used for user authentication.

## Escalation timeline
* 09:57 — L1 Security operations: Olu initiated an investigation into the reported authentication issues.
* 10:12 — L2 Security analyst: Diego took over the investigation, focusing on potential configuration problems with the MFA push-notification service.

## Diagnosis steps and hypotheses
Initial hypotheses centered around misconfigurations in the MFA service or issues with the LDAP directory. To troubleshoot, the `ldapsearch` command was used to query the user directory. Specifically, the following command was executed:
```
ldapsearch -x -H ldap://localhost:389 -b ou=users,dc=example,dc=com
```
This helped in verifying the connectivity and configuration of the LDAP server. However, it did not immediately reveal the root cause, suggesting that the issue might be more complex.

## Resolution steps
1. Restart MFA service on port 8080
2. Set push_timeout to 30 seconds
3. Update ldapsearch query to filter on ou=users,dc=example,dc=com
4. Verify session-trace logs for errors at /var/log/session.log

## Post-mortem note
The MFA push-notification service timed out due to misconfigured ldapsearch queries. This incident highlighted the importance of regularly reviewing and testing configuration settings for critical authentication services to prevent similar issues in the future.
