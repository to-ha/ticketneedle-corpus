## Symptom
Users intermittently received 401 unauthorized responses after successfully logging in, indicating a potential issue with session validation or authentication state. This symptom was observed across various client applications and was not specific to any particular user group or geographic location. The intermittent nature of the issue made it challenging to reproduce and diagnose.

Further investigation revealed that the 401 responses were often preceded by a successful login event, suggesting that the authentication process itself was not the primary cause of the issue. Instead, it seemed that the problem lay in the subsequent steps, possibly related to session management or directory replication.

The symptom complex was characterized by a brief window of successful access, followed by an abrupt termination of the session and a 401 response upon attempting to access protected resources again. This pattern hinted at a synchronization or replication issue within the authentication infrastructure.

## Diagnosis steps and hypotheses
Initial hypotheses focused on issues with authentication protocol configuration or network connectivity problems. However, as the investigation progressed, attention shifted towards directory replication, given the intermittent and post-login nature of the 401 responses. 
``` 
openssl s_client -connect node1:636 -showcerts
```
This command was used to inspect the SSL certificates used for secure communication between directory nodes, which provided critical clues about the potential misconfiguration of SSL certificates affecting replication.

## Resolution steps
1. Restart directory service on node1
2. Set replication interval to 300 seconds
3. Verify ldap port 389 is open on node2
4. Run ldapsearch with -x and -D flags

## Post-mortem note
Directory replication failed due to misconfigured ssl certificates. This incident highlights the importance of regularly reviewing and updating SSL configurations to ensure seamless directory replication and authentication services.
