## Symptom
The monitoring system alerted on a trace sampler rate misconfiguration, indicating that critical spans were missing. This issue was identified through an observable pattern of incomplete trace data, which suggested a problem with the log aggregation forwarder. Upon further investigation, it became clear that the missing spans were not being forwarded to the metrics platform, resulting in incomplete visibility into system performance.

The alert-history tool was used to review recent alerts and identify any patterns or correlations with the missing spans. The log-tail tool was also utilized to inspect the log-forwarder logs for any error messages or indicators of issues. Additionally, the trace-query tool was employed to attempt to reconstruct the missing traces and understand the impact of the misconfiguration.

## Diagnosis steps and hypotheses
Initial hypotheses focused on a potential misconfiguration of the log aggregation forwarder or an issue with the metrics platform. However, upon further investigation, it became clear that the issue was more complex. The team attempted to debug the issue by running the following command:
```
log-tail -f /var/log/log-forwarder/error.log
```
This helped identify some error messages related to buffer overflows, which pointed towards a potential root cause.

## Resolution steps
1. Restart log-forwarder service on node 3
2. Set max_buffer_size to 1024 in /etc/log-forwarder.conf
3. Increase timeout to 30s for log aggregation queries

## Post-mortem note
The log aggregation forwarder failed to send logs due to buffer overflow. This incident highlights the importance of monitoring and regularly reviewing log-forwarder configurations to prevent similar issues in the future.
