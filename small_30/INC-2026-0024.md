## Symptom
The filesystem metadata server was experiencing frequent failovers, occurring every few hours. This resulted in brief periods of unavailability for users attempting to access or modify files on the affected storage systems. Monitoring tools detected these failovers and alerted the on-call team, prompting an investigation into the cause.

Initial observations suggested that the issue might be related to the underlying storage infrastructure, given the nature of the failovers. However, it was crucial to gather more specific data to pinpoint the exact problem.

The failover pattern indicated a potential issue with the redundancy or failover mechanisms in place, possibly tied to the SAN multipath driver configuration. This driver is responsible for managing multiple paths to storage devices, ensuring high availability by automatically switching to an alternative path if one fails.

## Diagnosis steps and hypotheses
Initial hypotheses included a potential misconfiguration of the multipath settings or a hardware issue affecting one of the paths. To investigate, the team used tools like `iostat` to monitor disk usage and performance, `multipath -ll` to list and check the status of the multipath devices, and `fio` for more detailed storage performance testing.
``` 
iostat -x 5
```
This command provided insights into the disk utilization and throughput, helping to identify if there were any bottlenecks or issues at the disk level that could be contributing to the failovers.

## Resolution steps
1. Restart multipathd service with -v flag
2. Set max_polling_interval to 10 in /etc/multipath.conf
3. Remove failed paths using multipath -f
4. Verify path priority with multipath -ll

## Post-mortem note
The SAN multipath driver failed to properly configure path priorities. This issue highlights the importance of regularly reviewing and testing storage configurations to ensure high availability and performance. Further steps will be taken to implement more robust monitoring and automated testing for multipath configurations to prevent similar incidents in the future.
