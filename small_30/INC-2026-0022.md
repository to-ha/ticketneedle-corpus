# Major Incident — INC-2026-0022
- **Ticket ID:** INC-2026-0022

## Symptom
The network team observed asymmetric routing after a recent config push, which led to packet loss and increased latency for users relying on the anycast VIP. This issue manifested as intermittent connectivity problems, with some users able to reach the service while others could not. The symptom was first noticed by monitoring tools that track network performance and latency.

Further investigation revealed that the asymmetric routing was causing packets to take different paths to and from the destination, resulting in some packets being dropped or delayed. This was confirmed through the use of `traceroute` and Wireshark, which showed the inconsistent routing patterns.

The impact of this symptom was significant, as it affected a large number of users who rely on the anycast VIP for critical services. The network team prioritized resolving this issue to ensure consistent and reliable connectivity for all users.

## Escalation timeline
- 12:53 — L1 Network operations: Pavel alerted the L2 team about the issue after initial troubleshooting.
- 13:29 — L2 Network engineer: Sade took over the investigation, focusing on the anycast VIP configuration and recent changes.

## Diagnosis steps and hypotheses
Initial hypotheses focused on potential misconfigurations or recent changes to the network setup. The team considered the possibility of a routing loop or a misconfigured firewall rule. To investigate further, the team used the `nft` tool to inspect the current configuration:
```
nft list table ip filter
```
This helped identify potential issues with the anycast VIP rule, which seemed to be the root cause of the asymmetric routing.

## Resolution steps
1. Set nft table ip filter priority to 10
2. Update anycast VIP rule to use ip saddr 192.0.2.1
3. Reload nft configuration from /etc/nftables.conf

## Post-mortem note
The anycast VIP route was not properly configured with the correct IP address. This oversight led to the asymmetric routing issue, highlighting the importance of thorough configuration reviews and testing. The resolution steps effectively addressed the problem, and the network team will conduct a review to prevent similar configuration errors in the future.
