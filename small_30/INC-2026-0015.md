# Major Incident — INC-2026-0015
- **Ticket ID:** INC-2026-0015
- **Reported:** 2026-04-18 22:14 UTC
- **Priority:** P3
- **Domain:** Platform infrastructure
- **Status:** Resolved

## Symptom
The CI pipelines began to stall consistently on the same stage across all repositories. This symptom was first observed by the on-call engineer, who noticed that multiple pipeline runs were hanging indefinitely without any error messages. Further investigation revealed that the issue was not specific to a particular repository or branch, suggesting a more systemic problem. The stalling pipelines caused delays in the deployment of new features and fixes, impacting the development team's productivity.

As the incident unfolded, it became clear that the stalling pipelines were not producing any useful error logs, making it challenging to diagnose the root cause. The monitoring systems did detect an increase in the number of timed-out connections to the feature-flag service, which hinted at a potential issue with this component.

## Escalation timeline
- 22:29 — L1 Platform support: Zara notified the L2 team about the ongoing issue.
- 23:02 — L2 Platform engineer: Dmitri started investigating the pipeline stalls and began to suspect an issue with the feature-flag service.

## Diagnosis steps and hypotheses
Initial hypotheses focused on network connectivity issues or problems with the pipeline configuration. However, after running `registry-gc --debug` 
in a debug mode to inspect the registry, it became clear that the issue was more related to the feature-flag service's interaction with the registry. The evidence from the debug output pointed towards a potential caching issue within the feature-flag service.

## Resolution steps
1. Restart feature-flag service on node 3
2. Set cache ttl to 300 seconds in /etc/flag/config.yaml
3. Run registry-gc with --dry-run flag to identify unused flags

## Post-mortem note
The feature-flag service failed to update due to a stale cache. This incident highlights the importance of regularly reviewing and updating cache settings to prevent similar issues in the future. The swift resolution was possible due to the systematic approach to diagnosing the issue and the collaboration between the support and engineering teams.
