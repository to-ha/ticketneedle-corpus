## Symptom
The incident began with reports of intermittent packet loss on a single uplink, which was observed by both users and monitoring systems. This symptom was consistent across multiple checks using MTR, indicating a potential issue with the network configuration. Further investigation revealed that the packet loss was specifically affecting traffic routed through the OSPF backbone area.

## Diagnosis steps and hypotheses
Initial hypotheses focused on potential issues with the firewall rules or OSPF neighbor relationships. However, after running the command ```nft list table ip filter``` to verify the firewall configuration, it became clear that the issue was more likely related to the OSPF configuration itself. The diagnosis then shifted towards examining the OSPF area settings and network types.

## Resolution steps
1. Set ospf area 0 network type to point-to-point
2. Restart ospfd service on router 10.1.1.1
3. Update nft rule 100 to allow OSPF packets on interface eth0

## Post-mortem note
The OSPF backbone area was misconfigured with the wrong network type. This misconfiguration led to intermittent packet loss, as observed during the incident. The correction of the network type and the restart of the ospfd service resolved the issue, restoring full connectivity through the affected uplink.
