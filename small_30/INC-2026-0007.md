## Symptom
The BGP session flapping every few minutes was the primary symptom observed during the incident. This flapping caused intermittent packet loss, resulting in disrupted network connectivity for users relying on the WAN aggregation router. The monitoring system alerted the team to this issue, prompting an immediate investigation into the cause of the BGP session instability. Further analysis revealed that the BGP hold time was not optimally configured, potentially contributing to the frequent session flapping. The impact of this symptom was significant, as it affected critical network services and caused noticeable performance degradation.

As the incident unfolded, it became clear that the BGP session flapping was not an isolated issue but rather a symptom of a deeper configuration problem with the WAN aggregation router. The intermittent nature of the packet loss made it challenging to pinpoint the exact cause, requiring a thorough examination of the router's configuration and the network's topology. The team utilized tools like `dig` and `nslookup` to verify DNS resolution and check for any potential issues with domain name resolution that could be impacting BGP session establishment.

The observation of BGP session flapping led the team to suspect issues with either the router's configuration or problems with the network connectivity to the peers. However, as the diagnosis progressed, it became evident that the root cause was more complex and involved a specific misconfiguration of the WAN aggregation router. The symptoms observed were consistent with a routing instability issue, which further supported the focus on the BGP session flapping as the primary symptom to address.

Given the critical nature of the WAN aggregation router to the network's infrastructure, any instability in this component has a ripple effect, causing disruptions to services that rely on stable network connectivity. Thus, resolving the BGP session flapping issue was paramount to restoring full network functionality and preventing further service disruptions.

## Diagnosis steps and hypotheses
The team initially considered the possibility of a peer connectivity issue, given the nature of BGP session flapping. However, upon further investigation, including the use of `nft` to examine firewall rules and potential impacts on BGP traffic, it became clear that the issue was more likely related to the configuration of the WAN aggregation router itself. A key step in the diagnosis involved examining the current firewall rules with the command:
```
nft list table ip filter
```
This helped in understanding if any recent changes to firewall policies could be contributing to the BGP session instability.

Another hypothesis considered was the potential for a routing loop or inappropriate route reflection, which could cause BGP sessions to flap. However, analysis of the routing tables and consultation with network diagrams did not support this hypothesis, leading the team to focus more closely on the configuration of the WAN aggregation router and its interaction with BGP peers.

## Resolution steps
1. Restart router with config file /etc/network/config.txt
2. Set BGP hold time to 30 seconds in /etc/quagga/daemons
3. Update route reflector IP to 10.1.2.3 in /etc/network/routes
4. Apply new firewall rules with nft -f /etc/nftables.conf
