## Symptom
Users reported intermittent 401 errors after successful login, indicating a potential issue with the SAML federation gateway. This symptom was observed across various user groups and seemed to occur randomly. The error messages did not provide clear indications of the cause, leading to an initial confusion about the origin of the problem.

Further investigation revealed that the issue was not consistent and seemed to affect users at different times, suggesting a possible timeout or synchronization problem. Monitoring tools did not immediately flag the issue, as it was intermittent and did not trigger standard alert thresholds.

The symptom complex centered around the SAML federation gateway's interaction with user sessions, pointing towards a need to inspect the authentication flow more closely.

## Diagnosis steps and hypotheses
Initial hypotheses included a misconfiguration of the SAML gateway or an issue with the IDP metadata. To diagnose the problem, the team tried running `pam-test` to simulate user logins and observe any errors. Specifically, they used:
```
pam-test --saml --debug
```
This helped in understanding the authentication flow but did not immediately reveal the root cause. The team considered hypotheses around clock skew and SSL certificate issues but found no evidence supporting these theories.

## Resolution steps
1. Set saml.assertion.lifetime to 3600 in /etc/saml/gateway.conf
2. Restart saml-gateway service with systemctl restart saml-gateway
3. Verify IDP metadata at https://idp.example.com/metadata.xml
4. Decode SAML response with jwt.io equivalent decoder to check expiration

## Post-mortem note
The SAML federation gateway was configured with an incorrect assertion lifetime. This oversight led to intermittent session expirations, resulting in 401 errors for users. The correction of the assertion lifetime resolved the issue, and additional monitoring has been put in place to catch similar configuration mistakes earlier.
